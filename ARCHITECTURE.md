# Как устроен Jol Ustazy

Документ отвечает на вопрос «что где лежит и на что ссылается». Правила оформления —
в [STYLE.md](STYLE.md), состояние проекта и незакрытые задачи — в [HANDOFF.md](HANDOFF.md).

## Общая идея

Всё приложение — один файл `index.html`: разметка, стили, код и данные вместе. Это не
лень, а следствие двух требований: страница публикуется как артефакт claude.ai (там
принимается ровно один HTML) и её можно сохранить и открыть без сборки.

Для сайта из этого файла собирается версия потяжелее оптимизированная — `docs/`.

```
index.html ──► tools/build.js ──► docs/index.html   полный документ + мета + PWA
                    │              docs/signs/*.svg  картинки знаков отдельно
                    │              docs/sw.js        офлайн-кэш
                    └─ tools/split-signs.js
```

`index.html` — источник правды. **`docs/` руками не правится**, любая правка там
пропадёт при следующей сборке.

## Экраны

Все экраны рисуются в `#app`, переключение — вызовом функции, маршрутизации нет.

| Функция | Что показывает |
|---|---|
| `screenHome` | Главная: титул, блок про ассистента, готовность, режимы, история, «О проекте» |
| `screenPickMode` | Выбор между официальным экзаменом и режимом с ассистентом |
| `screenTopics` | Список двенадцати тем |
| `screenQuiz` | Вопрос: карточка слева, ассистент справа |
| `screenResult` | Итог попытки и разбор ошибок |
| `screenAbout` | О проекте, источники, лицензии |
| `screenRules` | Полный текст ПДД по главам с поиском |
| `screenSigns` | Каталог знаков |
| `screenSignDrill` | Тренажёр знаков: показывает знак, четыре названия на выбор |
| `screenMarkings` | Каталог разметки |
| `screenFines` | Таблица штрафов |
| `screenPmp` | Первая помощь: поиск, меню разделов, боковой список на широком экране |
| `screenProchie` | Прочие справочные материалы |

`render()` решает, что показывать, по состоянию `S`: нет `S` — главная, `S.finished` —
итог, иначе вопрос. Верхнее меню вызывает экраны напрямую, подсветку пункта ставит
`setNavActive`.

### Вопрос

```js
{t:'t5',                                    // тема, ключ из TOPICS
 q:'Текст вопроса?',
 img:()=>scene({cars:[...], arrows:[...]}), // необязательно
 o:['верный','...','...','...'],            // верный ВСЕГДА первым
 a:0,                                       // индекс верного
 e:'Разбор: объясняет правило'}
```

Верный ответ пишется под индексом 0 всегда. Позиция ничего не выдаёт: `makeQueue`
тасует варианты при выдаче и запоминает перестановку в `it.order`, а `it.correct` —
это позиция верного уже после перемешивания.

Казахская версия берётся из `KKQ` по русскому тексту вопроса. Порядок вариантов
обязан совпадать с русским: ответ хранится индексом, а не текстом. Перевода нет —
показывается русский, приложение остаётся рабочим.

### Схемы к вопросам

Три построителя, все возвращают строку с `<svg>`:

- `signFig(['коды'])` — знаки из набора `SIGNS`
- `scene({cars, arrows, lights, warden, zebra, peds, signs})` — перекрёсток
- `road({marking, cars, peds, signs})` — прямой участок

Геометрия перекрёстка: осевая вертикальной дороги `x=160`, горизонтальной `y=100`.
Правостороннее движение задаётся константами `APPR` и `EXITP`: едущий на север
держится правее осевой (`x=176`), на юг — левее (`x=144`), на восток — ниже (`y=116`),
на запад — выше (`y=84`). Знаки ставятся справа по ходу. Стрелки манёвров строятся из
тех же констант, отдельно их править не нужно.

## Виртуальный ассистент

Скриптовый, без ИИ и без сервера. Живёт в `assistPanel`.

**До ответа** — две кнопки:

- `helperBlock` → `makeHint(q, L)` — берёт из разбора первую фразу, в которой нет
  отличительных слов и **чисел** верного варианта. Проверка по числам обязательна:
  без неё в вопросах о скорости подсказка называла «140 км/ч», то есть выдавала ответ.
  Фраза находится у 172 вопросов из 251, остальным даётся общий наводящий текст.
- `findChapter(q)` — глава Правил. Тема жёстко привязана к главам через `TOPIC_CH`,
  внутри отобранных уточняется по совпадению слов. Раньше был свободный поиск, и он
  утягивал всё в главу 1, где собраны термины.

**После ответа** — разбор: что выбрали, что верно, почему, и где это в Правилах.

**Два режима** задаются в `start()`:

| Режим | Таймер | Проверка | Ассистент |
|---|---|---|---|
| `exam` | 40 минут | в конце | нет |
| `assist` | нет | сразу | есть |
| `marathon`, `topic`, `mistakes` | нет | сразу | есть |

## Тренажёр знаков

`screenSignDrill` — отдельная от базы вопросов механика. В вопросах проверяется понимание
правил, здесь — узнавание картинки, и для этого нужна не логика, а частое повторение.

Берётся случайный знак, у которого есть изображение. Три неверных названия выбираются
**из той же группы**: если брать из разных, ответ угадывается по стилю знака, а не по
знанию. После ответа показываются номер, группа и описание. Состояние держится в `DRILL`,
в `localStorage` не пишется — это разминка, а не прогресс.

## Картинки знаков: сопоставление по названию

**Нумерация знаков Казахстана и России не совпадает.** В группе 1 сдвиг на два пункта,
в группах 4 и 7 расхождения сильнее. Скачивание файла «RU road sign <наш номер>» дало
114 неверных картинок из 205: под казахстанским 4.9.2 «Опасные грузы» стоял российский
4.9 «Движение легковых автомобилей».

Спасает то, что файлы с Викисклада подписаны внутри: `<dc:title>3.1 Въезд запрещён`.
`tools/match-signs.js` сравнивает это название с названием нашего знака и берёт файл
только при **полном совпадении набора слов**. Частичного мало: «переезд со шлагбаумом»
и «переезд без шлагбаума» отличаются одним предлогом, а знаки разные — поэтому короткие
слова «без» и «со» из сравнения не выбрасываются.

Не совпало — знак остаётся без картинки. Пустое место честнее чужого знака.

**Знаки с текстом страны рисуем сами.** На Викискладе знаки начала и конца населённого
пункта подписаны российским городом, а «Общие ограничения максимальной скорости» —
надписью «РОССИЯ» с чужими цифрами. Первые перерисованы в `tools/make-locality-signs.js`
с названием «Астана», вторые убраны: их содержание зависит от страны, и придумывать
цифры нельзя.

**Схемы к вопросам не берём из интернета.** Чужие рисунки защищены авторским правом,
и ссылка на источник этого не отменяет. Всё рисуется своими построителями `scene` и
`road` — они наши и под MIT.

## Подсветка поиска

`highlightMatches(text, query)` **сама экранирует текст**. Значит, ей нужно отдавать
сырую строку, а собственное форматирование (например `**жирный**`) накладывать уже
на результат. Если сделать наоборот, вставленные теги превратятся в видимый текст —
на этом уже спотыкались в разделе первой помощи.

## Прогресс

Хранится в `localStorage` под ключом `zholtest.v2`, отдельно язык и тема.

```js
{done: {q12:{ok:2,bad:1}}, mistakes:['q12'], exams:[{d,r,n,p}]}
```

«Готовность» на главной — доля вопросов, отвеченных верно и не висящих в ошибках.
Формулу менять нельзя не глядя: она обещает человеку, что он готов к экзамену.

## Сборка

```bash
node tools/make-icons.js docs   # иконки PWA, достаточно один раз
node tools/build.js             # собрать сайт в docs/
```

Что делает `build.js`:

1. Делит `index.html` по `<header class="bar">` на голову и тело
2. Оборачивает в полный документ, добавляет мета для iOS, манифест, иконки
3. Вызывает `splitSigns` — вынимает base64-картинки знаков в `docs/signs/*.svg`
   и заменяет их короткими ссылками. Страница легчает на 1,3 МБ
4. Пишет манифест и service worker, версия кэша считается от содержимого

Имя приложения — объект `CFG` в начале `build.js`, плюс `<title>` и шапка `index.html`.

## Проверки после правок

```bash
node --check <извлечённый скрипт>     # синтаксис
node tools/build.js                    # сборка проходит
python -m http.server 8137 --directory docs
```

Осмысленно также прогнать все `img()` и убедиться, что каждая возвращает SVG без
`undefined` и `NaN`; сверить длину `kk.o` с `o`; поискать близкие дубликаты вопросов
(коэффициент Жаккара ≥ 0.55 — точные совпадения ловятся, смысловые нет).

Глазами: **393×852** (iPhone 16) и **1440×900**, обе темы, вопрос со схемой и без.
Живую страницу артефакта встроенный браузер не открывает — проверять на локальной
сборке или на опубликованном GitHub Pages.
